流程

0

相机标定板规格

填你手上那块棋盘的方格数（数格子），不是内角点数—— 程序会自动换算成 OpenCV 需要的角点数。导入素材时靠它判断"这张是棋盘照还是地面照"， 所以必须在导入之前设对。

方格至少 4×5 或 5×4；OpenCV 内角点：11 × 8

1

导入素材

把棋盘照和地面照混在一起的目录丢进来，按"能否检出棋盘"自动分拣。

只填文件夹名即可，会依次在工程根、data/、data/import/ 下查找；也支持绝对路径。

备份并清空

把输入/输出产物打包进 backups/，然后清空各目录，等待新素材导入。

2

相机标定

尚无首轮误差数据。
3

选择地面标定原图

接下来做逆透视（IPM，把这张透视图变成地面俯视图）。 从 ipm_input/ 中选择一张十字路口四个角点清晰、赛道边界容易辨认的照片。

4

导出

落盘六个矩阵和两类查找表（去畸变、去畸变+逆透视），每类各含正向/反向，共 4 组 LUT；随后运行批量测试。

只允许整数倍等比降采样。320×240 这类组合是非法的： 它让横向缩 4 倍、纵向缩 3 倍，16:9 的俯视图被压成 4:3，地面上 45×45 cm 的正方形 会变成宽高比 0.75 的竖长矩形，嵌入式端拿它算角度、曲率、横向偏差全部失真。

全尺寸文本表在 720p 下约 56 MB，单片机放不下。 二进制定点表 + 4×（320×180） 约 0.9 MB，是能上车的量级。 等比之后嵌入式端只需一个倍率 n：full = (small + 0.5) × n − 0.5。

地面标定矩形 · 实际尺寸

当前智能车赛道使用十字路口的方形区域进行标定，默认尺寸为 45×45 cm。若实际赛道尺寸不同，请以实测值为准。 这一项直接决定比例尺（px/cm）与车上距离测量的正确性。

量的是地面上那个矩形（四点框住的那一块）的外框边长， 与第 0 步「相机标定板规格」的棋盘格内角点数、方格边长是两回事，不要互相照抄。

目标地面范围 · 俯视图要看多大一块地

以逆透视坐标参考原点为原点，横向 ±(横向宽/2)、向前「参考点前方」这么一块地。 自动布局会把它完整装进俯视图并贴住底边。

逆透视坐标参考原点 = 去畸变图底边中点对应的那个地面点（预览图里的橙色十字）。 它只是人为选定的逆透视坐标参考点，不代表摄像头位置、不代表车辆几何中心、也不代表保险杠位置—— 源图底边中点对应的是「光心出发穿过该像素的视线与地面的交点」，通常在车前一小段距离处； 光心本身没有有限的像素坐标。所以这里写「参考点前方」而不是「车前」。

超出相机实际可见范围的部分留黑（无效），不会为了填满而把远处拉成放射状。
